# 파트 2 경로·매칭 에이전트 구조 — 2026.11.16 (현재 코드 기준)

이 문서가 지금 코드와 맞는 최신판이다. 예전 설계 문서(경로판정_에이전트_설계 11.05, 경로_매칭_통합설계 11.05, 파트2_코드구조 11.08, 파트2_업체매칭_설계 11.12)는 배경 참고용.

## 0. 한 줄 요약

파트 1이 보낸 폐기물 정보(WasteCase)로 **규칙 코드가** 법이 허락하는 처리 경로와 자격 있는 업체를 찾고,
**LLM·에이전트는 규칙이 남긴 빈칸만** 채워(대안 후보·표 초안) 파트 3에는 RouteProposal, 파트 1에는 InformationRequest를 보낸다.

## 1. 원칙

| 원칙 | 내용 |
|---|---|
| 판정은 규칙 | 경로 가능·불가, 업체 거르기, 법 기준 비교(발열량·물량)는 판정표(CSV) + 코드. 같은 입력이면 같은 결과 |
| LLM·에이전트는 빈칸만 | 표 초안 만들기, 업체 미확보 경로의 대안 찾기. 결과는 항상 "확인 필요"이고 판정 칸을 바꾸지 않음 |
| 법은 표로 | 법 내용은 코드가 아니라 data/tables의 표. 법이 바뀌면 표를 다시 만들고(staged) 사람이 확인(confirmed) 후 반영(promote) |
| 지어낸 것 차단 | LLM 결과는 원문 인용 대조, 에이전트 대안은 도구 결과에 나온 업체·코드·조문만 남김 |
| 모르면 묻기 | 빈 값은 추측하지 않고 질문(InformationRequest / 업체 문의) |
| 꺼도 돈다 | LLM·에이전트가 없거나 실패해도 규칙 결과는 그대로 나감 |

## 2. 전체 흐름

```
파트 1 WasteCase
   │
   ▼
[규칙]  1. search_routes    사전검증 → 관문 1(지정 순환자원) · 2(재활용 위탁) · 4(소각·매립)   (관문 3 제외)
[규칙]  2. validate_routes  근거 법령(laws), 에너지 회수기준 요건(requirements)
[규칙]  3. find_partners    역할별 업체 매칭(재활용·처분·운반·구매처), 거리순 상위 5 + 예비 5
[규칙]  4. compare_routes   업체별 운송 탄소 (처리 탄소는 참고)
[에이전트] 5. 빈칸 채우기   업체 미확보 경로만 → 대안 후보 (--agent, LangGraph)
   │
   ▼
[규칙]  6. 출력 만들기
        ├─ RouteProposal v1.1 (→ 파트 3): checks, partner_candidates, questions, document_triggers(+plan_check),
        │                                 related_laws(규칙 조문 원문), requirements, alternatives, comparison
        ├─ InformationRequest (→ 파트 1): 배출시설 여부, 발열량, 지정폐기물 사전 확인 등
        └─ 추천 카드 (→ 화면), 역방향 추천(처리업체 → 배출업체)
   │
   ▼
[규칙]  7. 회신 반영 (파트 3 PartnerFeedback) → 거절 업체 제외·예비 올림·재계산
```

## 3. LLM·에이전트가 들어가는 곳

| 어디 | 무엇 | 언제 | 결과 처리 |
|---|---|---|---|
| `law_api/draft_tables.py` + `llm_client.py` | 문장으로 된 법 원문 → 판정표 초안 (condition_texts, designated_check_targets 등) | 법이 바뀌었을 때 (오프라인) | 인용이 원문에 글자 그대로 있는지, 분류번호가 별표 4에 있는지 검증 → draft → 사람 확인 → confirmed |
| `agent/` (LangGraph) | 업체 미확보 경로의 대안 조사 | pipeline `--agent` | 도구 결과에 있는 것만 남김, `alternatives` 칸에 "검색 후보, 확인 필요" |
| (예정) 추천 이유 문장 | 추천 카드 설명 | pipeline 옵션 | 문장 속 숫자가 규칙 값과 다르면 버림 |

LLM 연결: 타임리 AI OpenAI 호환 주소 (`TIMELY_API_KEY`, `TIMELY_BASE_URL`), 모델 `anthropic/claude-sonnet-5.5`.
이 모델은 함수 호출 강제(tool_choice 지정)를 받지 않아서 `auto` + "반드시 도구로 제출" 지시로 쓴다. Anthropic API 직접 연결도 `LLM_PROVIDER`로 고를 수 있다.

## 4. 에이전트 상세 (`agent/`)

```
            ┌──────────── 도구 호출 있음 ────────────┐
 시작 ─▶ [llm 노드] ──▶ (조건) ──▶ [tools 노드] ──▶ (조건) ─┘
                          │                         │
                    도구 없음 → 끝        finish 호출 또는 8회 → 끝
```

| 도구 | 하는 일 | 안전장치 |
|---|---|---|
| `route_info` | 미확보 경로의 단계·처리방법 코드·업체를 뺀 이유 | 읽기만 |
| `allowed_methods` | 이 폐기물에 판정표(disposal_methods_5 / treatment_code_map)가 허용한 처리방법 코드 | 판정표 기준 |
| `rematch` | 처리방법 코드를 바꿔 업체 다시 매칭 (규칙 매칭 함수 그대로) | 허용 코드가 아니면 거부 |
| `other_routes` | 같은 폐기물의 다른 경로와 업체 확보 여부 | 읽기만 |
| `search_law` | 법령 조문 검색 (lawstore) | 결과 ref 기록 |
| `finish` | 대안 제출 (처리방법 변경 / 다른 경로 / 정보 필요) | 검증: 도구 결과에 없는 업체·경로·코드·조문은 버리고 `dropped`에 기록 |

- 파일: `agent/tools.py`(도구·검증), `agent/graph.py`(LangGraph, 없으면 같은 반복을 단순 루프로), `agent/__init__.py`(`find_alternatives`)
- 테스트: `AGENT_MOCK=1`이면 LLM 대신 정해진 순서로 도구를 부름 (비용 없음)
- 실제 실행 결과 (11.16, DEMO-PART2-02 지정폐기물 04-02-00 중간처분 미확보):
  도구 `route_info → allowed_methods → rematch ×2 → other_routes → finish`, 버린 대안 0
  → 대안: 판정표가 허용한 소각(2101·2102)으로 허가 업체 3곳(최근접 3.7km) / 이미 확보된 소각 경로 / 배출업체에 성상·전처리, 소각 업체에 인수 조건 확인

## 5. 폴더 구조 (코드)

```
src/route_agent/src/
├── preliminary/      사전검증 (분류번호·지정 여부·금지 확인)
├── gates/            관문 1·2·4 판정 (판정표 기반)
├── partners/         역할별 업체 매칭 (by_recycler, by_treatment, by_transport, by_end_user, rank, matcher)
├── carbon/           운송 탄소 (탄소_배출계수_v1.csv)
├── laws/             판정 근거 키 → 법령 이름·조항·시행일
├── lawstore/         법령 저장소: 조회, 발췌, RAG 검색, 조문 통째 + 항·호 개수 검증(articles.py)
├── law_tables/       법 기준 표 판정: plan_check(처리계획 확인), energy(에너지 회수기준), designated_check(지정폐기물 사전 확인)
├── law_audit/        누락 법령 점검 (인용 그래프 + 단계 키워드 + RAG)
├── proposal/         RouteProposal v1.1, checks, questions, documents, related_laws, info_request, feedback
├── recommend/        추천 카드, 역방향 추천
├── agent/            에이전트 (LangGraph)
└── pipline/pipeline.py   진입점 (--no-partners, --top, --feedback, --agent)

src/law_api/
├── law_core/         targets(대상 법령 22개, 감시 조문 번호+제목), api, chunker(항·호 counts), parts, store
├── law_chunk.py      법령 받기 → data/law/chunk_v2/{법령}/{시행일}.jsonl
├── law_watch.py      baseline / check(번호 이동 감지) / extract / refs
├── build_tables.py   원문 → 판정표 (코드 파서) → staged → diff → promote(안 바뀐 파일은 유지, confirmed 이어받기)
├── draft_tables.py   문장 원문 → 판정표 초안 (LLM)
└── llm_client.py     LLM 호출 (Anthropic 또는 타임리)
```

## 6. 데이터

```
(MS)/data/
├── tables/active/    판정 코드가 읽는 표 (staged → 사람 확인 → promote), old/ 백업
├── reference/        시군구 중심점, 탄소 계수
└── law/              chunk_v2/(법령 청크), raw/(원문, 공유 금지), watched/, reports/, llm_cache/
```
환경변수는 `(MS)/env.sh` 하나: `ROOT`, `WASTE_DATA_DIR`, `WASTE_REFERENCE_DIR`, `WASTE_LAW_DIR`. 인증키(LAW_OC, TIMELY_API_KEY)는 파일에 넣지 않고 실행할 때 입력.
